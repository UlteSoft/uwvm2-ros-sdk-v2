# Java and Kotlin AOT backend

[中文](README.zh.md)

TeaVM 0.13.1 consumes JVM class files generated by a Java or Kotlin compiler. The WROS port uses its C backend to emit code for the WROS Clang and Wasm linker. The C backend calls the application entry point synchronously, retains full-width guest references, and routes allocations through the nonmoving Wasm collector. The local Java driver enables TeaVM source positions and treats severe compilation problems as errors. [Driver](driver/Translate.java) · [Compiler backend](upstream/core/src/main/java/org/teavm/backend/c/CTarget.java) · [Allocation](upstream/core/src/main/java/org/teavm/runtime/Allocator.java)

The [source manifest](upstream.json) gives the official tag, commit, archive digest, and before/after digests of all 14 modified source files. The compiler projects, class library, tooling sources, Unicode and time-zone resource data reside in the upstream directory. The manifest enumerates the omitted IDE metadata and prebuilt Gradle wrapper JARs. Use Gradle 9.1.0 and a compatible JDK to work with the Gradle build. The x86-64 host Java frontend uses Eclipse Temurin 21.0.10+7. The review tree includes the OpenJDK compiler modules, HotSpot, JDK build files and the matching Adoptium distribution build scripts. The 25,333 retained JDK files and all 146 distribution-build files match the official Git blobs and modes. The omitted JDK root entries are `.github`, `.jcheck` and `test`. Module and third-party licenses are retained. ## Java compiler distribution

The native Linux `wrjava` executable starts the installed JDK, calls javac through its compiler API, invokes the patched TeaVM C translator and links through the selected native WROS C compiler. Each host record in `bin/packages/<host>/wrjava/java.json` pins the WROS launcher and selects the upstream JDK lock. The launcher build uses Zig 0.15.2 (Linux x86-64 distribution SHA-256 `02aa270f183da276e5b5920b1dac44a63f1a49e55050ebde3aecc9eb82f93239`). For example, `python3 -I -B src/compilers/jvm/rebuild_launcher.py --zig /absolute/zig --host linux-arm --work "$PWD/.tmp/wrjava" --output "$PWD/.tmp/wrjava-arm.tar.xz"` rebuilds the static ARM EABI5 entry. The published arm launcher targets ARMv5TE and armhf uses ARMv7, VFPv3 and NEON. The explicit SDK rebuild uses a native C11 compiler for the launcher. [Native source](driver/wrjava.c) · [Guest compiler](driver/WrosJava.java) · [Java installation](../../../document/en/languages/java.md)

On x86-64 the installer downloads Eclipse Temurin 21.0.10+7 from the Adoptium release. It verifies the original gzip archive, the complete tar stream and the recorded JDK members. On i686, AArch64, ARM soft-float and ARM hard-float it downloads Debian's `openjdk-21-jre-headless` and `openjdk-21-jdk-headless` 21.0.10+7-1~deb13u1 for i386, arm64, armel and armhf respectively. The locks identify the January 28, 2026 Debian security snapshot and the digests from its signed index. The installer uses `dpkg-deb` to extract Java, javac, javap, the module image, runtime libraries, configuration and legal notices. It resolves package-owned links and checks the native ELF ABI. The Debian host supplies its JRE system libraries, including libatomic for armel's Zero VM. The extracted image omits the Debian source ZIP link and the distribution-managed network trust store. [Temurin release](openjdk/upstream.json) · [Debian inputs and index](openjdk/debian/upstream.json) · [Debian runtime dependencies](https://packages.debian.org/trixie/openjdk-21-jre-headless)

The WROS TeaVM driver and runtime class binaries are awaiting publication. The source rebuild fetches 29 compiler JARs from Maven Central and install them under `share/toolchains/teavm/jars`. The WROS classes and runtime templates take precedence over the upstream JARs on the classpath. Source mode adds 11 external source JARs. On Debian JDK hosts it also restores the matching Debian source tarballs beside the signed `.dsc` in `src/compilers/jvm/openjdk/debian`. To unpack the source and Debian patches, run `dpkg-source -x openjdk-21_21.0.10+7-1~deb13u1.dsc` there. The installer verifies each official input by size and SHA-256 and reuses it across installations from `<prefix>/.cache/sha256/<sha256>`. A populated cache supplies these Java inputs offline. [Compiler JARs](java-jars.json) · [Dependency sources](java-source-jars.json) · [Installation](prepare.py) · [Debian JDK layout](package_inputs.py)

The five WROS launcher records pin their executable and compressed archive digests. Installation from the official inputs, execution through both VM engines, deployer execution, the selected native toolchain source rebuild, and upstream JDK and Gradle distribution rebuilds await independent qualification. Kotlin requires a separate frontend.
