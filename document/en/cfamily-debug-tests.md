# C, C++, Objective-C and Objective-C++ VM debugging, full restore and signed updates

The default run schedules 16 guest profiles, four installed frontends and three LLVM AOT capabilities. This plans 192 observations per host and 960 across Linux x86-64, i686, AArch64, ARM soft-float and ARM hard-float. The runner identifies the target host from the VM ELF header and records the controller architecture and optional emulator command separately. [Runner](../../src/qualification/cfamily/debug_suite.py) · [Fixtures](../../src/qualification/cfamily/debug_fixtures) · [中文](../zh/cfamily-debug-tests.md)

## Reproduce a host run

Use the offline qualification namespace with its 64 GiB limit, zero swap and project-volume scratch directory. Mount the installed prefixes for the selected languages, WAT for thread profiles, the target VM and its receipt, the reviewed VM commit/tree JSON, and the qualification files read-only. The runner needs Linux Python 3.11 or later with Ed25519 support from `cryptography`. Copy `debug_suite.py`, `debug_live.py`, `sysroot_suite.py` and the adjacent `debug_fixtures/` together. The compiler prefixes can be outside the checkout. [Namespace launcher](../../src/qualification/isolated.py) · [Reviewed VM target](../qualification/runtime-qualification.json)

Supply a directory containing three public VM support files with their original relative paths. Their SHA-256 pins come from VM revision `454a19a3c8c1ea388472d44589a126554067ef8b`. The accepted runtime revision comes from the reviewed target and the measured VM executable receipt. [Debugger transport](https://github.com/UlteSoft/uwvm2-ros/blob/454a19a3c8c1ea388472d44589a126554067ef8b/test/0018.debugger/run_dump_launch_policy.py) · [Snapshot decoder](https://github.com/UlteSoft/uwvm2-ros/blob/454a19a3c8c1ea388472d44589a126554067ef8b/tools/debug/snapshot.py) · [Signed protocol helper](https://github.com/UlteSoft/uwvm2-ros/blob/454a19a3c8c1ea388472d44589a126554067ef8b/test/0017.runtime/run_signed_update_boundaries.py)

The example uses paths visible inside the namespace. Set `--round-id` to the same identifier on all five hosts and use a fresh output directory for each run.

```sh
python3 -I -B /work/qa/cfamily/debug_suite.py \
  --cc-sdk /work/sdk/c --cxx-sdk /work/sdk/cpp \
  --objc-sdk /work/sdk/objc --objcpp-sdk /work/sdk/objcpp --wrwat /work/sdk/wat/bin/wrwat \
  --vm /work/host/uwvm2-ros --vm-receipt /work/host/receipt.json \
  --vm-target /work/pins/runtime-qualification.json --vm-support /work/vm-support \
  --work /work/results --round-id cfamily-acceptance-01 --jobs 2
```

For an initial x86-64 run add `--profile wasm32-wasip1-noeh-nomte`. Select a frontend with `--language c|cpp|objc|objcpp` and a capability with `--capability source-debug|full-dump-restore|signed-hot-update`. A targeted INT debugger rejection check requires an explicit `--engine int`, one profile, one language and one capability. For a cross-architecture VM, `--runner-json FILE` reads the exact command prefix as a JSON string array. The target process must retain its authenticated direct-parent channel.

## Evidence and verdicts

Each compiler builds its fixture twice with `-O0 -g` and the selected width, thread, MTE and EH flags. The runner checks both C/C++ build receipts. For Objective-C and Objective-C++, it verifies each sealed object against the installed frontend digest, GNUstep runtime receipt and expected guest profile, then links that object with the same installed frontend. It records the compilation and link commands and hashes the final module. For every language it inspects the final DWARF sections, public exports and implementation indices. Thread profiles use a bounded shared-memory owner produced by the installed WAT frontend.

Threaded Objective-C and Objective-C++ fixtures link with the installed WASIp1 command CRT. Each generation must export wasi-libc's `wasi_thread_start` and import `wasi.thread-spawn`. The main thread starts a worker to copy the input value 40 into a local variable. After `pthread_join`, it passes that value to the class method and checks that the result is 42. Under MTE this exercises wasi-libc's managed TLS allocation and retirement. The C/C++ fixtures and the single-thread Objective-C variants supply their own `_start` with `--reactor`.

- **Source debugging** sets a source breakpoint on the addition, reads `local == 40`, steps to the next marked statement in the original file, reads `local == 42`, and resumes to a checked zero exit. The Objective-C fixtures stop inside the class method reached by the message send. The Objective-C++ method obtains the input through a C++ template. The result identifies whether the debugger reported the terminal state or the original child’s OS wait supplied its exit code after the acknowledged resume.
- **Full restore** stops at an actual Wasm entry, writes four bytes to guest memory, saves a full archive, checks its embedded guest bytes, and overwrites the live word. A positive result requires the old word at the saved Wasm location under a fresh stop after restore, followed by successful execution and exit. The result records the size and completeness of the Wasm state. Guests with no Preview1 import run with their unused Preview1 environment disabled. `--restore-timeout` gives the first restore request and all pending replies a shared deadline in seconds (default 900) for rebuilding resumable native code. The snapshot is kept inside the private results directory. [VM snapshot contract](https://github.com/UlteSoft/uwvm2-ros/blob/454a19a3c8c1ea388472d44589a126554067ef8b/documents/runtime/unified-snapshot.md)
- **Signed hot update** starts a separate VM with debugger permission `none` and a dedicated authenticated update stream. An in-memory, one-use Ed25519 key signs launch, prepare and commit. The same process calls the approved `value()` export on the same channel and nonce, returning 17 at epoch 1 and 29 at epoch 2. Receipts include the installed image hash and the prepared and READY measurements. [VM production update contract](https://github.com/UlteSoft/uwvm2-ros/blob/454a19a3c8c1ea388472d44589a126554067ef8b/documents/runtime/production-update.md)

`inputs.json` records the installed SDK selections, tool digests, round, VM receipt and namespace identities. `build.json` binds both generations to the compiler, source and sysroot. Each capability has its own `result.json` under the profile, language and engine. `results.jsonl` collects the rows. `summary.json` counts positive results and expected negative assertions independently. Retain VM logs, live command records and dumps within the isolated output volume.

For private thread sessions, the source-debug and full-restore probes record the first-instruction stop in `thread_entry_stop`. A capability refusal counts as `unsupported` only after the authenticated VM reports that stop with a positive stop ID, a thread ID and its Wasm location. A private VM that reports a terminal state at startup yields `failed`.

`pass` records a positive capability. A separately selected INT DBG check earns `expected-rejection` only with exit 126 and the explicit interpreter diagnostic on the authenticated launch. A debugger that answers a request fails that check. `unsupported` records a recognized refusal from the VM. `restore-declined` requires an explicit restore rejection and verification of the retained original stop and changed memory. `failed` records an unexpected outcome. `build-blocked` records a build failure. Any of these last four outcomes makes the runner exit nonzero. Only `pass` contributes to the positive count.

### Objective-C MTE signed-update refusal on x86-64

For `wasm32-wasip1-noeh-mte/objc`, the installed `wroc` linked both generations with `--reactor --export _start --export value`. In both images, bytes `08 01 02` at file offset 553 encode Core start section 8, selecting function 2, `__wasm_memtag_init_globals`. The exported `_start` is function 218. The SHA-256 digests are `89fca1523d9c5c6aa61bd571a4f169448f26799b74bdebbc216915a0e8cce90b` for generation 1 and `e22c0c8affe2c69e13059b6bbbd01256d28581e932837ab0fc07ed21b2b261cb` for generation 2. [Objective-C frontend](languages/objc.md) · [SDK linker](../../src/compilers/cc/llvm-project/lld/wasm/Writer.cpp)

The x86-64 VM candidate at `d5524f35c565` reported `production update profile requires a single owned module without a start section` and exited 126 before answering the first UUP1 status request. The original run recorded an EOF. The launch image and VM diagnostic establish `unsupported` for this signed-update result. The runner records each generation’s start section in `build.json` and treats a status reply on this restricted launch as a failure. [VM contract at the measured revision](https://github.com/UlteSoft/uwvm2-ros/blob/d5524f35c565c60e4c2d92d9328afc8314c5803f/documents/runtime/production-update.md#supported-changes-and-execution-boundary)
