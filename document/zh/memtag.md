# WasmMTE 的检测范围

所有已提供 MTE 配置的开发入口默认生成插装。用户可以为整个目标选择关闭，并使用对应的 sysroot。源码属性可以改变局部插装。审核时应分别看目标配置、作者的显式属性和编译器自动消除的指令。

## 标签比较

本 SDK 使用的 WasmMTE 软件后端以 16 字节为一个粒度。wasm32 有 4 个标签位，wasm64 有 8 个标签位。同步模式下，普通读写必须逐个检查这次访问触及的粒度。任意一个分配标签与指针标签不符，这次访问就必须失败。旧版独立抽样策略允许相邻对象偶然同色。位于同一带标签粒度内的子对象越界也可能通过标签比较。

对一个固定标签，若另一个标签从全部编码中独立、均匀选取，单次不匹配的概率为 wasm32 的 15/16 和 wasm64 的 255/256。相同标签的旧指针反复访问同一对象并不会产生独立抽样。libc 的堆分配把零保留给元数据和已释放的空间，活跃堆对象从非零域抽取。两个独立活跃堆标签不相同的概率分别为 14/15 和 254/255。在释放后、再次分配前，旧的非零标签与已清零的粒度一定不同。这些数值都不能作为整个应用的错误检出率。

## 受管分配的近邻规则

VM 在实际持有线性内存的对象上统一分配标签。两个活跃或已预留的独立范围，如果它们占据的 16 字节粒度之间最多隔着 64 个字节，必须异色。这也覆盖紧邻对象、短分配器头以及多个模块对同一内存的导入别名。分配时同时检查地址两侧的所有近邻。物理 MTE 路径还排除低 4 位与近邻相同的所有编码。零保留给无主存储。预留失败不会发布指针或标签。

| 编译器可以证明什么 | 目标程序如何处理 |
| --- | --- |
| 值完全在寄存器中 | 没有需要打标的线性内存对象。 |
| 两个指针引用同一活跃对象 | 派生指针和跨语言传递都保留该对象的标签。 |
| 两个独立对象必须同时存活，最终布局也能证明相近 | 为两个对象保留各自的登记，指针逃逸前完成预留或打标。无法证明边界或生命周期的访问保留检查。 |
| 相对地址取决于链接、动态分配、导入或线程调度 | VM 解析实际底层内存和地址，排除所有近邻颜色，再从合法集合抽取。 |

仅凭源码声明顺序无法断定栈或链接布局。释放后原址重用属于新的生命周期，空间上的近邻异色也不能充当永久代次标识。

在这个半径下，左右边界各检查最多五个外部粒度。每个近邻受管对象至少占一个粒度，因此即使对象大小和释放顺序不固定，近邻同时存活的数量仍有界。

在剩余合法颜色中均匀抽取，使给定禁用集合下的熵最大。乘法映射配合拒绝不完整区间，避免候选数不能整除 65,536 时出现偏差。远处对象可以复用颜色。上述 15/16 和 255/256 描述的是全域独立抽样实验；近邻检查有自己的确定性条件。应用的错误检出率还受对象布局和生命周期影响。[无偏区间抽样论文](https://arxiv.org/abs/1805.10941)

各语言的分配器和解释器必须为每个需要独立保护的范围登记。工具链验收对应具体编译器、运行库、VM 与目标组合。自定义内存池以及共用一个粒度的子对象需要调整布局或增加更细的边界检查。即使解释器已经编译为 Wasm，其访客语言对象也可能共用同一块内存池，需要单独验证。

## 线程局部对象

Wasm 链接器在提取静态库、删除未使用的代码和链接时优化之后，检查最终仍然存活的 TLS 符号。当前多线程 libc 可能把 TLS 放进一块已有堆分配或调用者提供的栈。各个线程退出路径尚未实现逐对象登记和回收，因此严格链接会拒绝含有存活且已标记 TLS 数据的多线程镜像，诊断会指出涉及的符号。可重定位链接会把该信息保留到最终链接。独立链接器提供显式的 `--allow-legacy-tagged-tls`，用于采用旧分配策略的构建；此类产物不满足受管近邻保证。

## 自动删除标签的条件

对栈对象，编译器必须证明经其地址及派生指针执行的每个可达访问都在对象边界内，且发生在对应的生命周期内。调用者和被调用者之间传递地址时也要成立。无法证明的索引、调用目标或指针逃逸应保留插装。若还要省略整个对象的标签，必须另证其他对象发起的访问无法在缺少边界或生命周期检查时进入该范围。若对象在优化后完全位于寄存器中，则没有需要用标签保护的线性内存访问。源码显式关闭插装的声明属于作者的选择，不能充当编译器的安全证明。

## 如何复核

在 64 GiB 验收 cgroup 中，用重新构建的工具链和 VM 运行以下测试。两者都接受 `--toolchain PREFIX --runtime VM --work NEW_DIRECTORY`，每次在 SDK 的 `.tmp` 下使用不同的新目录。

- `tests/memtag_stack_generations.py` 覆盖循环、提前传出指针，以及 17 个或 257 个同时存活的栈对象。测试用编译后的实际地址判定近邻并逐对检查标签。
- `tests/memtag_global_pointer_origins.py` 链接两个分别编译的翻译单元。一个数组的合法尾后指针与下一个数组的首指针具有相同的数值地址。测试检查它们各自的标签、数组内部指针，以及通过各自所属数组进行的合法读写。

两个测试都覆盖 wasm32 和 wasm64，同一份客体程序分别在解释器与 AOT 引擎上启用和关闭 MTE。结果记录实际工具与 Wasm 产物的摘要。

完整 C sysroot 还可用 `tests/memtag_tag_domain.py` 验证。传入 `--toolchain`、`--runtime`、一个或多个 `--sysroots` 收据及新的 `--output` 目录。单线程无异常闭包使用 `--exceptions noeh`。普通读写覆盖每一种标签差值，各组均包含标签匹配的正对照。跨粒度用例在专用测试缓冲区的第二个粒度上逐位检查标签。另有四次 VM 调用验证活跃与已释放的堆存储。
