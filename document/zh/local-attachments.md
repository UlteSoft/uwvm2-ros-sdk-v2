# 本机驱动与模型接入边界

SDK 程序调用已经登记的 ROSv2 驱动或模型接口，不直接打开宿主套接字、选择
对端 PID、读取 TLS 私钥、切换命名空间、加载厂商动态库或创建原生驱动。
编译语言绑定、选择厂商平台，都不会自动取得这些权限。

受信部署层为每个获准的 VM 与服务会话分配独立通道，并向 VM 宿主交付已连接
的本机套接字、不可修改的身份材料、准确的进程凭据和时钟域证据。Wasm 只取得
明确授权的能力句柄。完成传输握手并不授予操作权，接口暴露与具体资源授权仍须
分别满足。多个 VM 共享驱动时，受信外部接收端必须对全部客户端统一仲裁。

当前 VM 使用 TLS 1.3、固定的 Ed25519 原始公钥、临时 X25519 密钥交换和
AES-128-GCM。宿主身份描述符包含自己的密钥种子与准确的对端公钥，并由内核
封存，禁止改写。私钥不得放进 Wasm 内存、应用 XML、命令行值或安装清单。
未来加密配置扩展须由部署策略准入，不向 Wasm 暴露任意密码学降级开关。

双方使用不同的非 root 用户时，部署层还交付对端时间命名空间的只读描述符。
VM 检查内核对象类型，并确认双方处于同一单调时钟域。部署层必须在进程执行前
固定其命名空间关系；cgroup 资源限额本身做不到这一点。VM 仍检查进程生存期、
逐包凭据和 TLS 身份，双方不需要获得对方进程的 ptrace 访问权。

部署层还会在启动或恢复工作进程前登记宿主身份。各部署器必须共享
[宿主所有权登记](https://github.com/UlteSoft/wasmros-deployer/blob/main/document/zh/host-identities.md)。
复用身份不能代替驱动能力授权；宿主身份协调、设备独占和 ROSv2 权限分别管理。

命名空间描述符是宿主登记参数，不改变 Wasm 调用的载体 ABI。不需要宿主权限的
计算继续留在 Wasm 中；受控的外部行为使用 ROSv2 接口。不要用通用 WASIp1
套接字或进程内原生预加载绕过驱动授权。

当前 Rust 部署器可以运行已审核的 VM，但在执行阶段仍拒绝原生驱动声明。
完整驱动编排和物理设备所有权生命周期尚未完成。跨用户接入验证使用可丢弃
Linux 来宾中的测试部署脚本，不代表全部厂商兼容，也不构成实体机器人安全认证。

宿主详细约定见 VM 的[驱动接入文档](https://github.com/UlteSoft/uwvm2-ros/blob/main/documents/runtime/ros-driver-attachment.md)
和[模型接入文档](https://github.com/UlteSoft/uwvm2-ros/blob/main/documents/runtime/ros-model-attachment.md)。
