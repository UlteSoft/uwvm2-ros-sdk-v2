# Franka ROS 2 CDR records

The C, C++, Rust and Go bindings encode and decode 137 encapsulated XCDRv1 PLAIN_CDR records. Franka ROS 2 3.6.0 supplies 18 arm and gripper definitions and 12 spine definitions. The bindings expand those into 77 and 35 records respectively. Seven standard ROS 2 packages supply the other 25 records. C, C++ and Rust use caller-owned storage. The Go module serves standard Go and TinyGo and decodes dynamic fields into owned strings and slices. The codecs operate on local buffers. [Arm and gripper interfaces](https://github.com/frankarobotics/franka_ros2/tree/4acc05c01ebfcdf916ee6b3df966df0ad7b2f9ec/franka_msgs) · [Spine interfaces](https://github.com/frankarobotics/franka_ros2/tree/4acc05c01ebfcdf916ee6b3df966df0ad7b2f9ec/franka_spine/franka_spine_msgs)

## Frame and field semantics

Pass the four-byte encapsulation header followed by the message. Identifier 0 selects big endian and 1 selects little endian. Scalar alignment starts immediately after the header and continues across all nested fields. Fixed arrays carry exactly their declared elements. Sequences begin with a uint32 element count. The two sequences in a service event each hold zero or one element. A string begins with a uint32 byte count including its terminal NUL. Public string views expose the preceding bytes. Constants occupy no bytes. An empty rosidl component contains one uint8 placeholder, initialized to zero. [Rosidl struct template](https://github.com/ros2/rosidl/blob/9bcfabf3eddf8e63fb4332dca6da7ec6f3140d65/rosidl_adapter/rosidl_adapter/resource/struct.idl.em) · [Fast-CDR implementation](https://github.com/eProsima/Fast-CDR/blob/9f4e60f7ac958e0fbbfe949102de3929cbbc226f/src/cpp/Cdr.cpp)

Decoding checks the complete frame, including nested lengths, boolean values of 0 or 1, string terminators and bounded sequences. Writers zero alignment padding and emit zero encapsulation options. Readers accept a zero options word or a low two-bit transport padding count consistent with the decoded length. A declared tail may be present or already removed by the transport. Other trailing bytes fail validation.

The schema preserves physical quantities as declared. For Elbow, the first position component is joint 3 angle in radians and the second is the sign of joint 4 relative to its flip angle. The commanded derivatives give joint 3 velocity in rad/s and acceleration in rad/s². Libfranka reports zero in the second derivative slots. For the spine, the absolute move defines position in metres and positive velocity, acceleration and deceleration. The codec validates structure. The upstream service or action server owns operational checks and permissions. A guest can build, read and transcode these bytes with an empty platform capability list. [Libfranka robot state](https://github.com/frankarobotics/libfranka/blob/3cc708cafa1cdba49ceaab536a14216dfb7bf48a/include/franka/robot_state.h) · [MoveAbsolute action](https://github.com/frankarobotics/franka_ros2/blob/4acc05c01ebfcdf916ee6b3df966df0ad7b2f9ec/franka_spine/franka_spine_msgs/action/MoveAbsolute.action)

## C

Include `<uwrosv2/franka/cdr/records.h>` or a package header such as `<uwrosv2/franka/cdr/franka_msgs.h>`. Record names combine `uwrosv2_franka_cdr_`, the package and the exact component name, for example `uwrosv2_franka_cdr_franka_msgs_Elbow`. The record's `_DATATYPE` macro gives its full ROS type name.

- `T_defaults()` initializes declared defaults, including nested grasp tolerances of 0.005 m and the identity quaternion.
- `T_encoded_size(&value, &size)` measures the frame. `T_encode(&value, order, dst, capacity, &written)` chooses `uwrosv2_franka_cdr_big_endian` or `uwrosv2_franka_cdr_little_endian`.
- `T_decode(src, size, &value)` assigns its output after the whole frame passes validation. `T_validate(src, size)` checks the same framing and fields. These operations return 1 on success and 0 on failure.
- For a sequence of doubles, use `uwrosv2_franka_cdr_float64_sequence_values(data, count)`. Read its `count`, obtain an iterator with `_sequence_iter(&seq)` and call `_sequence_next(&iter, &value)`. Record sequences use the element record's name in place of the primitive prefix.

## C++98 through C++26

Include `<uwrosv2/franka/cdr/records.hpp>` and use `namespace cdr = uwrosv2::franka::cdr;`. Types retain the package namespace, for example `cdr::franka_msgs::Elbow`. Start with `T::defaults()` for declared ROS defaults. The rosidl `T_Constants` namespace exposes constants with their declared integer width. Each record also exposes the constant names for integral expressions. Each service exposes `Request`, `Response` and `Event`. Each action groups its payloads and both services, for example `cdr::franka_msgs::PTPMotion::SendGoal::Request`.

Use `cdr::encoded_size(value, size)`, `cdr::encode(value, cdr::little_endian, dst, capacity, written)`, `cdr::decode(src, size, value)` and `cdr::validate<T>(src, size)`. They return `bool`. Use `cdr::Sequence<T>::from_values(data, count)`, `seq.size()`, and `seq.iter().next(value)`. Keep the iterator to read multiple elements. The C++ implementation uses `throw()` in C++98/03 and `noexcept` from C++11 onward.

In C and C++, a decoded string or sequence borrows its immutable input frame. Keep that frame readable until the last access, including iteration and re-encoding. A constructed sequence borrows its typed array under the same rule. Encoding measures the complete frame before writing. Keep writable output and count slots disjoint from every input span and from each other.

## Rust

Import `wros_observation::cdr::{Endian, Message, Sequence}`. Types live under `wros_observation::cdr::<package>`. `T::default()` applies declared defaults. `T::decode(frame)`, `T::validate(frame)`, `value.encoded_size()` and `value.encode(Endian::Big, &mut out)` return `Result`. `Error` distinguishes invalid encapsulation, padding, truncation, trailing data, invalid booleans or strings, a sequence bound, a length overflow and insufficient output space.

Strings borrow `&[u8]`, fixed arrays are native Rust arrays and `Sequence::from_values(&items)` borrows a typed slice. Use `seq.len()` and `seq.iter()` to inspect it. The type system ties borrowed views to the source lifetime. The `Service` and `Action` traits associate protocol components by type. The crate uses `no_std` throughout.

## Go and TinyGo

The public module is `github.com/UlteSoft/uwvm2-ros-sdk-v2/franka`. Import `cdr/frankamsgs` below that path for the semantic-component state, arm and gripper, and `cdr/frankaspinemsgs` for the spine. For example, `frankamsgs.DefaultFrankaRobotState()` initializes the nested pose quaternions, and `frankamsgs.DefaultGraspGoal()` initializes the inner and outer tolerances. `MarshalCDR(order, dst)` writes either byte order, `MarshalBinary()` allocates a little-endian frame, and `UnmarshalCDR(src)` reads either. Decoded values can outlive the input. Each example is a standalone Go module and uses the compiler, Xmake and VM from the selected installation. [Go and TinyGo packages, wire rules and external projects](../../include/u2rosv2/platform/franka/go/README.md)

## Offline examples

The selected installation contains `examples/franka/<language>`. For C, C++ and Rust, open its `cdr` subdirectory for the full typed example. Set `UWVM_ROS_SDK_ROOT` and `WROS_VM`, then run `xmake build` and `xmake test -j1`. The guest transcodes an Elbow sample in each direction, reads the seven joint angles and velocities from Franka's PTPMotion test and records the 0.42 m reply from the spine GetPosition test in a service event. All operations use local guest buffers. [Upstream PTPMotion sample](https://github.com/frankarobotics/franka_ros2/blob/4acc05c01ebfcdf916ee6b3df966df0ad7b2f9ec/franka_hardware/test/ptp_motion_test.cpp#L147) · [Upstream spine position sample](https://github.com/frankarobotics/franka_ros2/blob/4acc05c01ebfcdf916ee6b3df966df0ad7b2f9ec/franka_spine/franka_spine_server/test/test_spine_controller.py#L311)

The two 84-byte Elbow frames are independent outputs of eProsima Fast-CDR v2.2.5. Its diagnostic values exercise both slots in every array, including the second component of each commanded derivative. The source tree records both frames and their SHA-256 in `src/platform/franka/elbow_fixtures.json`. Run `python3 -B src/platform/franka/generate_cdr.py` in the SDK checkout to regenerate the C, C++, Rust and observation code from the fixed inputs.
